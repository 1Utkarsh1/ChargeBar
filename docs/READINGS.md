# Battery readings and limits


- **Adjusted estimate (≈):** the main number adds 1 percentage point to the smoothed prediction, with a maximum of 100.00%: `display = min(100, prediction + 1)`. Thus 56.89% becomes ≈57.89%, and 99.20% becomes ≈100.00%. The menu bar, large panel number and progress bar all use this adjustment. It is a display preference and can show 100% before the battery is physically full; charging status still comes from macOS. When raw capacity is unavailable, the whole macOS percentage is shown without an offset.
- **Underlying prediction:** starts at the raw gauge percentage, then integrates valid signed battery current over elapsed time using full-charge capacity. It prefers instant current over averaged current, and fresh gauge readings correct the estimate over a few seconds. Prediction continues beyond 60 seconds while current is valid; changing between charge and discharge preserves the number and reverses its trend. It holds when current is unavailable or incompatible with the new charging state, and reanchors after system sleep or a long polling gap. To prevent unbounded drift, it stays within two percentage points of the latest gauge value and shows "Waiting for battery gauge…" if it reaches that limit. This predicts intermediate values; it does not measure the battery to 0.01% accuracy. The +1 adjustment is applied after this calculation.
- **Raw battery gauge:** remaining capacity divided by full-charge capacity, shown separately without prediction. Hardware publishes these values in steps; reading faster cannot force new sensor data.
- **macOS battery level:** the operating system's rounded battery level. It may differ from the raw estimate because macOS applies its own battery presentation rules.
- **Into/from battery:** battery power telemetry in watts, with voltage times signed current as a fallback. During a cable transition, stale current or power with the wrong sign is withheld until a compatible reading arrives. The connection icon and state update independently of this electrical settling time.
- **Power into Mac:** live adapter input telemetry, including energy used to run the computer. This differs from battery charging power.
- **Charger capacity:** the adapter's reported capacity for its current connection. This is a limit, not the actual live charging rate.
- **Until full:** the system estimate, shown only while charging. It may change with workload and charge management.
- **Battery time left:** estimated time until the battery runs out, shown in the panel and menu bar tooltip. It prefers the macOS time-remaining estimate while discharging. If unavailable, it calculates `remaining mAh ÷ discharge mA × 60` minutes from the reported battery current. It uses raw capacity, without the +1 display adjustment. Charging shows "Charging", external power without measurable drain shows "Not draining", and missing/near-zero discharge data shows "Calculating…". A weak adapter that still allows battery drain also gets a runtime estimate. Workload, reserve capacity and battery condition can change the result; low-battery sleep or shutdown may happen sooner.

When decimal capacity is unavailable, the app shows the whole system percentage. Missing power readings appear as unavailable. A transient read failure holds the last value for up to three seconds and labels it "Waiting for battery data…"; a longer failure clears it. A subsequent successful poll or power notification restores it automatically. The IORegistry diagnostic keys can change in a future macOS release; this build was checked on the owner's current Mac. No charging limits or power settings are changed.
